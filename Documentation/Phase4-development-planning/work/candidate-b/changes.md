# Phase 6 iteration and version control

The owner calls for review, justified changes, updates to affected conceptual and design documents, a new plan version, development under that revision and version information in commits. Endpoint paths remain unversioned. Internal representation and envelope versions follow the accepted compatibility contract. [Phase obligations](../../../Phase1-conceptual/assumptions.md#phase-obligations) · [REST](../../../Phase3-LLD/rest.md) · [Internal envelopes](../../../Phase3-LLD/tooling.md)

1. Open a change record with observed issue, root cause and evidence, cited requirement/decision, proposed correction and alternatives, impact on scope, contracts, migrations, retained records, rollbacks, grants, vendors, risks and expected results. Identify any signoff or owner authorization the proposal affects.
2. Review with the coordinator, reviewer and relevant domain leads. Obtain owner approval before adopting a material change. Record source revision, owner receipt and exact conditions. Protect approved run and distribution scopes.
3. Update affected conceptual and design modules first, preserving old revisions and decision provenance. Then update trace, risks, ticket graph and milestone exits in a new Phase 4 revision. Retain stable ticket IDs or explicit predecessor/successor links for split or superseded work. Record revision, cause, exact source baseline and manifest. Review and sign the new package before reassigning.
4. In changed Phase 5 work attach red/green evidence and migration and compatibility cases from affected predecessors and successors. Add plan revision, ticket IDs and approval/evidence references to commits. Keep endpoints as adopted unversioned paths and verify retained clients/records. Run required gates on the merged artifact.
5. Close only when the changed objective, reviewers, exact evidence and release disposition are recorded. If verification regresses, return to the justified-change record. Promote and publish only under their applicable scopes and receipts. [Work protocol](execution.md) · [Production release](production.md)
