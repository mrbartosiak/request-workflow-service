# Early warning and fallback

Use this register before claiming each milestone. The coordinator tracks blocking evidence. Executors record failures and isolate symptoms, reviewers check the response and the owner approves material scope or operating changes. Keep affected surfaces closed while required proof is missing. [Phase 1 risks](../../../Phase1-conceptual/production-risks.md) · [Gates](decision-gates.md)

| Failure and earliest detection | First response, fallback and owner |
| --- | --- |
| Context drift, incompatible changes or merge silently loses a rule. Detect source digest/matrix mismatch at assignment, parallel contract test conflict or post-merge baseline change. | Coordinator pins exact sources and seams. The reviewer rejects untraceable output. Pause only conflicting merge, rebase and rerun both card regressions. Escalate material interpretation at G3/G7 or Phase 6. |
| Required SDK or build runner diverges, packages unavailable, blocker in network/provisioning. Detect in `FND-00/01` using exact JDK/toolchain resolution and reproducible fresh build. | Build lead uses explicit Java 25 path/session or approved environment, supplies compatibility options for G0. PG-independent checks proceed after approved bootstrap. Keep unavailable evidence blocked. |
| Fixture or test barrier differs from actual database isolation, wrong endpoint or locking order. Detect on startup/reset invariants, target alias/role, blocker probe and budget counters in `PG-01/05`. | Data lead isolates fixture, aborts timed-out scenarios, captures lock graph and compares setup. Retry deterministic cases. The owner chooses new fixture parameters through G2a/G2b. |
| Race, unknown commit or expired/old key hints at prior receipt. Detect P1–P9 on HTTP, rows, proof and retry budgets, including no lookup on expiry. | Transaction owner gates new effects, preserves original key/binding and resolves trusted lineage. Reopen only proved scope/target. The data lead reviews failed race. DFR-1/6 before target operation. |
| Rewind revives revoked access, IDs, payload or inbox. Detect old process, untrusted journal prefix, association, hold or inlet coverage before any reopening. | Reliability and data leads fence writer, egress and affected admission, verify original evidence or keep scope/target closed. Use audited resolver and staged rehearsal. DFR-1/2/3/6 gate changes to production authority or RPO. |
| Confidential fields, secrets or stale grant escape. Detect E2/E3/E4, denied row/cursor behavior, synthetic log scans, rotation/revocation checks and packaging inventory. | Security/privacy leads stop output or distribution, restrict the affected path, restore current authority and remove contaminated copies under approved policy. Escalate mappings, retention and visibility through DFR-2/3 or G6. |
| Throttling, vendor drift or unsafe delayed retry. Detect fake lag/UNKNOWN, stale lookup and tenant fixture mismatch early. | The integration lead isolates the destination, quarantines unsafe work and reconciles by verified proof. Unrelated destinations continue. Keep live work disabled or paused pending DFR-4/G8. |
| Log sink, pressure or advisory/quality hole. Detect gaps, spool fill, budget breaches, stale dependency inventory or critical gate failure at E7. | Operations lead restrict admission and drain, build/security leads re-evaluate findings and gate proofs. Record evidence gaps. DFR-5/6 and owner exception before scoped promotion. |
| Underreported timing or invalid acceptance target. Detect missing offers, per-op failures, hot waits and generator error before or during paced measurement. | Verification lead invalidates suspect run, keeps raw observations and isolates pace/lock/pool/authority constraints. QS has fixed scope. G4/G5 cover material proposed profiles/runs. |
| Deadline, failed clean checkout, pending decision or publication unsafe. Detect at critical-path review and `DEL-01` dry run. | Delivery lead rehearse reviewed source-only snapshot, state remaining evidence and use G6 for exact publication conditions. Owner decides dates and changes to deliverable or approved release scope. |

At incident declaration capture affected scope, situation, version, detection time, containment, rollback/restore acceptance and evidence gaps. Responsibility returns to the normal card owner only after reviewed recovery and relevant owner disposition.
