# Publish proof after receipt cleanup

Design against B21 `2cbe78606476dab4467e3ca260f2b51f3cdad212`, tree `087cc5dc4b838130060d406f98a99542e06769bc`. Add a workflow migration that preserves exact receipt evidence when a Publish receipt reaches the adopted cleanup cutoff. The receipt can then leave the replay store while the certified original publication remains available for confirmation and projection rebuild. This is a storage correction under D1-R. It needs no new owner-policy decision. ## Current dependency

The v1 witness points to the complete live receipt key through a foreign key. Its proof view also joins that row and requires the same PostgreSQL transaction for the witness, published request, final Publish fact, and exact finalized receipt. The command already checks the held gate and organization guard, then compares the complete finalized receipt on the same command connection before appending the witness. The independent resolver adds the certified original writer identity, exact attempt coordinates, the original transaction's committed status and the independent receipt identity digest. A COMMITTED attempt whose local projection needs rebuilding reads the same proof view under the exclusive organization guard. Dropping the live foreign key alone would permit cleanup and remove the evidence needed at those last two cuts. ## Proposed additive workflow v3

1. Add an explicit `JdbcPublicationWitnessMigration.migrateReceiptRetirement()` after v2. Reuse the workflow migration lock and transaction and extend the version constraint to allow 3. Add a v3 SQL resource loaded as a complete trusted SQL script on that connection because it contains PL/pgSQL bodies. Leave existing migration resources and records intact. Gate production cleanup on the installed schema version.
2. Add an owner-protected, append-only row per retired Publish receipt. Store the witness attempt ID as the primary key and foreign key, the original full workflow transaction ID, and the receipt's observed `xmin`. The existing witness retains the scoped receipt identity already needed for independent comparison. The retirement row carries only commit provenance and offers no replay payload or lookup path.
3. Establish the replacement safeguards before removing the exact witness foreign key to the live receipt. Use an immediate `AFTER INSERT` check to require the exact finalized Publish receipt when writing a new witness. Retain the Java gate, scoped full-receipt comparison and append order. At the database boundary, require the exact scoped key, action, state, revision, writer generation, namespace, ID and status. Require the full witness transaction to equal the current transaction and the receipt's `xmin` to match it. Prevent a bound live receipt key from being changed through an identity-column update. Keep the receipt's own deferred finalization constraint and the witness references to the request.
4. During physical cleanup, a restricted `BEFORE DELETE` trigger on the live receipt looks up its witness by all four key columns. An ordinary non-Publish receipt without a binding follows ordinary cleanup. A Publish receipt with no witness stays in place for investigation. For a bound receipt, require exactly one witness and require that its full original commit evidence matches before storing the retirement row. An inexact, ambiguous or conflicting binding stops the deletion. The insert and deletion commit or roll back together. Give the trigger only the owner privileges it needs for the exact evidence read and archival insert, use a fixed search path and fully qualified names, and expose the source relation only through the existing restricted view. Keep direct writes to the retirement table away from command, observer, projection and cleanup roles. Index the witness key lookup used by the delete guard. The existing authorized caller supplies the trusted-time cutoff of expiry plus 24 hours. The trigger preserves evidence and imposes no new time source or schedule.
5. Replace `requests.publication_commit_evidence` in place, preserving column names, types, order and the existing observer/projector grants. Factor the live receipt predicates so the INSERT safeguard, cleanup capture and live proof can check the same linkage without weakening it. Preserve the original witness, request, fact, transaction and version comparisons on every read. The receipt predicate can pass with the exact live receipt or with a matching retirement row and complete absence of the live key. A present but inexact receipt blocks the retirement path. The archive's later insertion transaction establishes the cleanup event. The original transaction remains the provenance of the Publish effect and is checked against the witness and independent reservation.

Under this approach a legacy v1/v2 witness needs no rewrite or backfill. Its live receipt remains the proof source until the ordinary delete transaction can certify its replacement. Rewriting a legacy witness to mark it retired would change the `xmin` used in the same-commit proof. An absent or inexact legacy receipt supplies no basis for creating a retirement row. An exact delete retry finds no live row and therefore creates no additional evidence. Native qualification must check the real foreign-key catalog, trigger privileges, two-transaction visibility, and view changes before enabling this version. ## Confirmation and recovery

- A PENDING attempt remains PENDING through cleanup. First confirmation can use the retired receipt evidence on the certified original workflow only when the exact current witness, request, fact, independent attempt, receipt identity and original committed status all agree. Unknown original transaction status still defers under the existing live-lineage proof.
- A COMMITTED attempt keeps its independent decision and ID. Rebuild a missing local projection from the exact original evidence under the exclusive organization guard. A durable projection and current scope remain prerequisites for protected reads and dependent dispatch.
- After restore, receipt absence, retirement absence, missing original effect, or divergent coordinates leave proof fenced. A retirement row on a copy does not certify that copy as the committing writer. A pre-cleanup image can contain the live receipt again. The signed cutoff still precedes receipt lookup and effect arbitration after submitted access and current scope are proved.
- Use the existing `ReceiptStore`, journal APIs, resolution roles, HTTP routes and dispatch gates. Keep B18's separate Create-receipt evidence rule in its own acceptance boundary.
