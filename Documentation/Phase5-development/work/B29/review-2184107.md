## B29-R3 · An admitted response can outlive its proof transaction

The recovery filter calls the servlet sink inside a shared PostgreSQL transaction. After the admission query, the application can pause before transferring the first protected status, header or byte. The proof backend is idle in its transaction during that pause. The qualified connection has a 12-second idle-in-transaction timeout. If that backend terminates, PostgreSQL releases the shared row lock. The independent owner can then acquire the exclusive row lock and complete containment. The old servlet handler still holds its response target and can resume output. The byte cap limits the staged body size. It imposes no time limit on scheduling or synchronous output. [Traffic admission](../../../../tmp/phase5-development/b29-independent-v2/qualified/adapter-authority/src/main/java/com/company/requests/adapter/authority/JdbcRecoveryTraffic.java) · [Proof transaction lifecycle](../../../../tmp/phase5-development/b29-independent-v2/qualified/adapter-authority/src/main/java/com/company/requests/adapter/authority/ProofTransactions.java) · [Configured timeout and stop action](../../../../tmp/phase5-development/b29-independent-v2/qualified/fixtures/postgresql/QualifyPostgresql.java)

The filter propagates transport failure and treats an uncertain proof commit after output as an unknown completion. That prevents it from sending a second response. Detecting the failure after the sink runs cannot withdraw its first write. The fixture physically stops the workflow postmaster and asserts that response egress is closed. Its attestation has no independent evidence that a handler which lost its proof session has relinquished its response target. A correction must keep exclusion certification closed while such a handler can still release protected data. Its control should cover loss of proof after admission and before the first raw output, and establish when the old handler has drained or been physically fenced. This finding comes from exact-source inspection.
