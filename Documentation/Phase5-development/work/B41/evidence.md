## Implementation and outgoing contract

- The servlet filter generates a UUID and records a start before authentication, MVC validation or routing. Problem responses reuse that UUID in the existing `correlationId` and `instance` fields. Synchronous filter failures and MVC results produce one outcome and, on failure, one error. The synthetic Tomcat access callback captures requests rejected before servlet dispatch. It uses the connector's elapsed time when available and emits one retrospective start followed by the error and outcome. The connector fallback checks the servlet marker to avoid double counting. [HTTP boundary](../../../tmp/phase5-development/b41-structured-evidence/adapter-http/src/main/java/com/company/requests/adapter/http/RequestEvidenceFilter.java) · [Connector callback](../../../tmp/phase5-development/b41-structured-evidence/bootstrap/src/synthetic-http/java/com/company/requests/bootstrap/SyntheticConnectorEvidence.java)
- Each record carries a UTC instant, generated correlation UUID, direction, operation and destination aliases, phase, catalogued outcome, failure stage, fixed description, monotonic elapsed nanoseconds and observed HTTP status when applicable. The current HTTP aliases are `CREATE_REQUEST`, `ISSUE_OPERATION_KEY` and `UNMATCHED_HTTP`. The standalone listener emits the typed JSON lines to its private synthetic transcript. The packaged JVM uses JUL for Spring and Tomcat. The opt-in main removes those unstructured handlers before configuration and emits a fixed startup failure diagnostic. The start returns a generated correlation and the finish accepts confirmed, rejected, unknown, timeout or failed. Both take finite catalogues. B42 owns worker invocation, protected spool, reservation and admission. The internal `RestrictedEvidenceLookup` takes an issued capability before invoking its read source and reports lookup access to a separate audit sink.
