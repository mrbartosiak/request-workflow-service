# B18 mapping handoff

`ExternalMappings` is the guarded integration entry point. Configure a trusted source policy that assigns each `(sourceSystem, tenant, identifierType)` to its organization, eligible target types and publication requirement. Authorize bind, business use and recovery separately. The key preserves the exact input bytes. The authority store assigns one stable binding ID to the exact key and proved target. A proved incompatible association quarantines the key and preserves the accepted binding. The JDBC registry uses a digest for indexing and arbitration, then compares bytes and all three scope coordinates for identity.

`bind` takes the target organization guard, proves current scope and reads the original committed Create fact and receipt. When applicable it proves the original publication via B17. The independently durable reservation precedes the local projection. The original certified writer may complete an equivalent reservation after a failed projection commit. A later generation with an absent projection uses `recover` and requires trusted evidence of the exact original committed effect. A mismatching local projection fences the key. The native observer verifies the original certificate retained with the registry and exact committed effect. A trusted retained proof source can implement `OriginalEffect` when the original observer is unavailable.
