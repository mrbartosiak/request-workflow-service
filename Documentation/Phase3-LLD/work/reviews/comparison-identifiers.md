# D1 · Identifier allocation and associations

**Governs** DEC-13/08, F-01/05, Q-02/03/10, R-02/09/10. The later owner instruction governs. Globally unique opaque Create references, positive increasing signed 64-bit Publish IDs, gaps, lossless JSON strings, common initial uniqueness and stable external mappings are binding. The mechanism and namespace label are proposed. [Owner identifier record](../../owner-identifier-requirements.md)

**D1-R recommendation.** Use one permanent initial Publish namespace across all initial types and organizations, as proposed by both candidates. Use C1's random opaque globally reserved Create reference and increasing epoch/ordinal. Prefer C2's ref-bound pending/committed publication journal and transaction witness. Keep proof-store product, topology and authority open. Registry round trips and stored reservations add cost for Create, and synchronous Publish proof adds a latency and availability dependency. Include it in the smoke. [C1 identifiers](../candidate-1/identifiers.md) · [C2 identifiers](../candidate-2/identifiers.md) · [C2 association protocol](../candidate-2/publication-reconciliation.md)

| Guarantee | Reference implementation and proof |
| --- | --- |
| Numeric exclusion | An independently durable high-water excludes earlier issued/reserved values within the namespace, including after deletion, rollback, migration or restore. Burn on abort and stop before overflow. Prove the migration starting high-water. |
| Increasing assignment | Lock the namespace on the current writer from before reservation through local commit or rollback. The next contender reserves after the first local transaction ends and receives a higher value. Successful assignment is at durable local Publish commit. Network responses and later confirmation may arrive out of order. Prove physical old-writer exclusion across generations before new assignment. |
| Stable published association | Before local effect, independently persist a pending binding of ref, namespace, ID, attempt and generation. Commit its witness with state, history, receipt and outbox. Confirm against trusted original lineage before success release and applicable dispatch. Missing restored rows cannot prove abort. Recover the same complete effect and original ID, or fence the ref even on a new key. Fence the namespace if coverage is uncertain. Authorized replay and any future approved republication preserve that ID. |
| Scoped mappings | Bind source system, tenant, identifier type and external ID to the committed ref and any confirmed original publication pair. Preserve independently witnessed reservations through rewind and migrations. Reconcile equal bindings and quarantine conflicts. A new namespace needs collision and compatibility proof. |

**Old-backup check.** Backup shows A ACCEPTED at high-water 817. Publish A as 818 and lose the response. Burn 819 on rollback and commit 820 elsewhere. On restoring the image, 821 is the first possible new reservation assuming no later reservation and verified old-writer exclusion. That exclusion proves only numeric safety. Restore A with 818 from trusted effects or keep A fenced. Repeat with local commit before confirmation and without a vendor mapping. Check old observations, old keys and separately proved current disclosures. [C2 restore checks](../candidate-2/restore-evidence.md) · [C1 recovery](../candidate-1/recovery.md)

| Alternative | Trade-off and impact |
| --- | --- |
| D1-I · Durable reserved ranges | One active range per namespace/generation can amortize allocation calls. Require serialized commit order, non-rewinding range cursor, old-range retirement and the same ref-bound association proof. Adds exhaustion, delayed-writer and partial-range fixtures. |
| D1-C · Derived Create reference | C2 pairs a permanent generation with a committed ordinal and opaque keyed encoding. Reduces per-Create external registry traffic. Requires a transactional creation gate, proof provisional refs never escape before commit, permanent format/key registry and migration/rotation tests. |
| D1-D · Defer | Keep cross-type uniqueness, stable explicit namespaces, increasing IDs per namespace, lossless wire and non-reuse binding. Defer namespace construction, storage and authority mechanism. Plan old-backup checks. Publishing remains gated where proof is unavailable. |

**Verification** Include cross-type concurrent commits above 2^53, rollback, exhausted counter, generation exclusion, confirmed and unconfirmed lost-response publication, preservation of original ref/ID, scoped mapping and audited known/unknown loss. The production restore path remains a separate approval and proof. [C1 P7/P9](../candidate-1/postgres-evidence.md) · [C2 recovery](../candidate-2/recovery.md)
