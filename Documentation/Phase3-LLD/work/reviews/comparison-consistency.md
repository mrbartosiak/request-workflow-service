# D1 · Transactions, retries and restore

**Governs** DEC-03/08/13, F-01–05/09, Q-02/03/10/13, R-01/02/08/10. Production engine and storage remain deferred. PostgreSQL is the retry-evidence candidate. D1 also selects the identifier mechanism. [Identifiers](comparison-identifiers.md) · [Approval groups](../../owner-approvals.md) · [Owner direction](../../owner-kickoff.md)

**D1-R recommendation.** Use atomic transactional state, ordered history, minimal receipts and obligations. Prefer C1's conservative organization guard with key arbitration first, then the exclusive guard and request/fact locks for new mutations. Replay and protected release take the guard shared. C2 takes the scope gate before the key and allows shared mode for writes proven to leave security-visible inputs unchanged. The C1 option avoids classification mistakes and keeps key arbitration observable. It reduces concurrency in a busy organization. Every relevant write takes an incompatible gate through commit and the fresh protected release holds its gate through local response handoff, including browse lookahead. Keep declaration of writer admission, external calls and commit phases explicit in the reconciled transaction order. [C1 persistence](../candidate-1/persistence.md) · [C1 access](../candidate-1/access.md) · [C2 transactions](../candidate-2/transactions.md)

Both candidates favor signed expiring keys scoped to stable principal/organization across routes, a semantic digest and unique-key arbitration. Propose 24 h validity and 24 h cleanup lag. C2's seven-day window gives clients longer replay and retains more digests. All new effects require the active writer. A new existing-request write also needs fresh action context. Create has no observation. An exact authorized replay preserves original outcome and precondition bytes, where applicable. Resolve uncertain commit using the same key on certified authority. [C1 retries](../candidate-1/retries.md) · [C2 retries](../candidate-2/retries.md) · [C2 observations](../candidate-2/observations.md)

**Separate proofs.** Block old observations after rewind. For signed keys, forbid new effects from earlier generations and use one fence across absent, concealed and unproved old receipts. Signed expiry requires no receipt lookup. The UUID alternative uses scope completeness and marker evidence. Trusted replay and both-side authorized conflict require current disclosure. Unproved current authority closes protected reads, replay, writes and new dispatch authorization. High-water exclusion, publication association and current authority need separate evidence. [Restore cases](../candidate-2/restore-evidence.md) · [Authority](comparison-access.md)

| Alternative | Trade-off and proof |
| --- | --- |
| D1-L · Conditional writes | Use guarded comparisons on the request, state and every material fact version. May reduce some explicit waits. Keep incompatible ordering with protected handoff and prove no losing write leaves history, receipt or outbox. Query predicates, database compatibility and all race outcomes need re-review. |
| D1-S · Scope-before-key locking | Select C2's writer admission, then declared scope mode, then key and target/fact locks. Allow shared writes only for inputs proved to leave security visibility unchanged. May reduce contention and adds qualification/classification work. Verify actual wait point, no lock upgrade and protected handoff. |
| D1-K · Client keys | Client UUIDs and durable markers skip key issuance. Scope, marker retirement, proof-gated admission and protocol differences are specified separately. [UUID protocol](comparison-client-keys.md) |
| D1-D · Defer | Continue engine-neutral ports and the PostgreSQL fixture design. Keep transaction protocol, key contract and identifier mechanism provisional. No production persistence/workflow implementation or write reopening can rely on the unselected proof. |

**Phase 4 and verification.** Plan deterministic two-service PostgreSQL checks with a real primary, barriers, observed locks and a separate verifier. Cover same-key match/different intent, independent identical Creates, competing actions, rollback after atomic append, post-commit response loss, unknown commit, revocation before release, old key concealment and old-backup proofs. Repeat equivalent tests on the production engine before qualification. Owner selection covers the reference strategy. Engine-specific settings, exact storage and named authority still need decisions.
