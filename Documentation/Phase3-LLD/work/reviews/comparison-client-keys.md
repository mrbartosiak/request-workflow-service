# D1-K · Client-generated UUID protocol

**Governs** DEC-04/05/08, Q-02/03/13. This alternate elaborates the candidates' client-key and retired-marker option. Adopting D1-K replaces only D1-R's signed-key protocol. The atomic effects, authority and observation contracts still apply. [D1 choices](comparison-consistency.md) · [C1 retries](../candidate-1/retries.md) · [C2 retries](../candidate-2/retries.md)

**Intake.** Document one validated canonical UUID text form in `Idempotency-Key` for every write. Clients generate the UUID, keep it and the original semantic intent for retries, and generate a fresh UUID for a new intent. Remove the key-issue endpoint and its permission. Key bytes assert neither expiry nor generation. Bind intake to authenticated issuer, organization and stable principal across routes/aliases. Require active writer and current scope proof. A fresh action observation applies only to new existing-request writes. Create has no observation.

Maintain a complete independently recoverable record of accepted keys in each open scope. The production choice can use a journal with durable admission reservations and exact committed effects or establish equivalent complete coverage from trusted retained commit history and writer fencing. A local database receipt still commits atomically with the business effect. Definitive rollback allows same-intent arbitration. A rewound local miss cannot prove a fresh UUID or close a pending attempt. During a gap, fence new key use for the affected scope, including apparent new UUIDs. Open only after verified coverage. | Case after submitted-intent access and authority checks | D3-R observable behavior under D1-K |
| --- | --- |
| Active scope and authoritative absence | A genuinely new UUID may enter normal atomic arbitration and validation. |
| Trusted exact receipt or trusted changed intent | Replay original result under current authorization. Return 409 `key_conflict` for changed intent only with current access to both sides. |
| Complete scope, trusted retired marker | 409 `retry_fenced` if original access is authorized. If the original is inaccessible, return ordinary concealed 404. Both have no prior result fields or headers. |
| Retired or unproved scope/coverage | Uniform 409 `retry_fenced` for a disclosable submitted intent and unresolvable prior history, including absent or concealed receipts. Existing authorized proofs can replay only if trusted and current authority is established. |
| Current authorization authority unavailable | Generic 503 authority outcome applies before any prior history selection. No protected output or effect. |

Use D3's ordinary input, disclosure and uncertainty errors. The UUID alternative uses independent key-history coverage to decide whether a key can start an effect after rewind. `key_expired` is exclusive to signed keys. Bound intake with per-scope quotas and limits. After approved result-retention expiry, keep compact no-reuse markers with protected original authorization scope. Discard a marker only after its authenticated scope permanently closes to old keys, including aliases and re-enrollment, or equivalent enforceable no-reuse proof exists. Until then, reserve storage or block new admissions safely. [D3 wire](comparison-wire.md)

**Verification.** Restore a backup older than an acknowledged Create and omit its local receipt. Recover the original if independently proved and authorized, or fence and verify no duplicate. Deny an unseen UUID while coverage is incomplete. Allow one Create once authoritative absence is proved. For an inaccessible retired key in a ready scope, compare ordinary 404 body and headers with the concealment fixture and verify zero effects. Compare missing versus concealed receipt during a coverage gap. Expect identical 409, no result headers and zero effects.
