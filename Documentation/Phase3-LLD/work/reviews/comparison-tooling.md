# D5 · Tooling and dependency choices

**Governs** A-02/03, Q-04/07/08, DEC-06/10/14. Both signed candidates agree on the recommended starting approach for all six items. Each item is independently selectable. A tool pilot authorizes a trial and evidence. Deployment or mandatory gating requires compatible pinned versions and reviewed results. | ID | D5-R recommendation and authority | Actionable alternate and evidence | Bounded defer |
| --- | --- | --- | --- |
| T1 · YAML DTO generation | T1-R. Reviewed OpenAPI YAML owns wire shape. Use explicit Spring MVC records initially and exercise matching examples in CI. | T1-A. Pilot OpenAPI Generator models only. Reduce DTO duplication, with template/annotation and Boot-assumption costs. Prove clean Java 25/Spring 7.0.11 build, optional fields, masking, decimal-string IDs and repeatable output at compile/CI. | T1-D. Postpone generation through Phase 4 and protect the wire with manual fixtures and spec review. |
| T2 · Compile-time mapping | T2-R. Wire DTOs and permitted projection types are authoritative. Use explicit Java constructors and mapping tests. | T2-A. Pilot MapStruct on mechanical mappings. Adds annotation processor and build maintenance. Prove unmapped-field failures, null/omission, no sensitive leakage and Java 25 compilation. | T2-D. Keep manual Java and reopen when repeated mapping volume warrants review. |
| T3 · Breaking API detection | T3-R. Pilot pinned oasdiff CLI at PR/release against the last approved released OpenAPI baseline. Pair with Spring behavior tests. | T3-A. Manual spec diff plus MVC/consumer fixtures avoids the CLI and adds review effort. For the pilot prove route removal and ID string→number fail, and safe additions pass. Both paths test masks and errors. | T3-D. Keep compatibility evidence manual until the wire baseline and gate owner are approved. |
| T4 · Schema-derived DB types | T4-R. Approved migrations own storage shape. Use Spring JDBC explicit row mapping and real-engine migration tests. | T4-A. Pilot jOOQ after engine selection on a disposable migrated schema. Prove licence, generated type/constraint mapping, stale-column detection, reproducible build and compatible schema upgrade/rollback. Costs include dialect, generator and runtime choices. | T4-D. Defer generator through production engine decision and retain hand-written mappings in the PostgreSQL fixture. |
| T5 · Schema-derived event payloads | T5-R. Use explicit versioned minimal obligation envelopes and CI fixtures. Keep payload schema separate from domain classes. | T5-A. Pilot Avro when consumer/transport contract is agreed. Schema resolution may help multiple consumers. Adds codec, registry or compatibility tooling. Prove old/new reader fixtures, retained payload replay, allowed fields and Java 25 reproducibility. | T5-D. Defer event generation through live-consumer approval. Keep versioned fake fixtures. |
| T6 · Package-boundary tests | T6-R. Pilot test-only ArchUnit at PR/release using the approved module/package graph. Use build-module edges regardless. | T6-A. Use module build and JDK dependency inspection plus explicit assertions. Lower library cost, more manual upkeep. Prove that domain→Spring, prohibited adapter imports and cycles fail, and that valid wiring passes on Java 25. | T6-D. Defer extra test dependency and maintain manual boundary/compile checks. |

D5-D can defer all six choices with manual proof paths. With D3-D and T3-R, use a seeded fixture for the API diff pilot. A production gate needs the approved released spec. Exact servlet/JSON provider, JDBC driver/pool, build versions and Spring Security integration depend on approved runtime, engine and identity protocol. Prefer standard Spring services. A manual auth adapter needs equivalent issuer, rotation and scope tests. Test dependencies stay outside runtime.
