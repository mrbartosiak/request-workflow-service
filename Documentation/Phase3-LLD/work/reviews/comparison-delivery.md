# D4 · Module and delivery choices

**Governs** DEC-08/09/10/14, A-03/06, F-10/11, Q-07–09, R-04/05/10. Composed core and extensions in one deployable release are approved. Exact package edges, worker bounds and fixtures need selection. Live vendors and priorities remain deferred. [Kickoff](../../owner-kickoff.md) · [HLD architecture](../../../Phase2-HLD/architecture.md)

**D4-R recommendation.** Keep C1's explicit inward dependency from HTTP, JDBC and delivery adapters to the application/core. The application owns the outbound append contract. The JDBC append joins the workflow command transaction and connection. Separate delivery pools claim/finalize committed obligations in the same database. Keep vendor ports typed, providers behind connectors, and Spring assembly in one bootstrap with explicit bean wiring. C2's five-module layout has fewer build units. Retain its clear durable ARMED/send/confirm distinction within the C1 ownership boundaries. [C1 wiring](../candidate-1/wiring.md) · [C2 wiring](../candidate-2/spring.md) · [C2 delivery](../candidate-2/delivery.md)

For C1's fixture budget, start with four worker and four dedicated database slots per instance, batch 8, max two concurrent attempts per tenant/destination cluster-wide, 15 s lease, 2 s call timeout and up to five proven-safe transient attempts within 15 min. Keep ordered effects behind their unresolved predecessor. Include the full destination/tenant/effect identity in attempt records. Deduplicate inbound by trusted source identity domain, compare declared type, version, target and semantic digest, and quarantine incompatible reuse. Atomic receipt plus effect or a processing obligation precedes acknowledgment. Only current certified grants permit new sends. [C1 delivery](../candidate-1/integration.md) · [C2 delivery](../candidate-2/delivery.md)

For ambiguity, require proven single-effect behavior for the same stable key over all possible arrivals, or prove older sends cannot apply and verify authoritative absence. An expired lease only prevents stale local finalization. Quarantine unproved attempts, including after restore. Publication-dependent dispatch also requires its confirmed association. [C1 remote evidence](../candidate-1/verification.md) · [C2 publication protocol](../candidate-2/publication-reconciliation.md)

| Alternative | Trade-off and impact |
| --- | --- |
| D4-M · Five-module layout | Select C2's core, web, storage, delivery and runtime modules. Keep the append port in core and its implementation on the workflow command connection. Fewer build units make compiled package checks important inside each module. Verify the same rollback, dependency and extension cases. |
| D4-W · Per-instance writer cap | Add C2's limit of one outbound writer per destination per instance. Retain C1's cap of two concurrent attempts per tenant/destination cluster-wide. This can increase backlog on one available instance. Exercise local and cluster caps, queue age, ordered streams and unrelated destinations. |
| D4-B · Broker relay | Retain the atomic local append and add a durable relay. Increases independent scaling and adds a failure boundary, evidence needs and operations. Test handoff, duplicates, backpressure, replay, fencing and migration. |
| D4-D · Defer | Keep shared port sketches and fake conformance scenarios. Package/pool sizing and broker/storage commitments remain provisional. Live work remains deferred for every option. |

**Two-instance check.** With one tenant/destination and independent eligible sends, D4-R allows two concurrent attempts including a 2+0 or 1+1 placement. D4-W allows at most one outbound writer on each instance, so two writers require 1+1 and one healthy instance can send only one at a time. The cluster cap stays two attempts in both options. An ordered successor still waits for predecessor proof under either cap. Test local throttling with just one instance ready, then recovery of the second.
