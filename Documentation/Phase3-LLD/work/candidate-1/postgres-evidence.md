# Deterministic PostgreSQL retry evidence

**Scope** A-04, F-01/02/05/09, Q-02/03/13, R-01/02/08/10, DEC-03/08/13. Proposed verification specification. Status **planned, unrun**. This evidence is independent of the performance check. [Transactions](persistence.md) · [Retry contract](retries.md)

Run two service processes A/B with separate pools, shared real PostgreSQL 18 on a pinned minor, and independent identity authority. Use fresh data, authorized observations and minted keys. Latch at key claim, pre-commit and pre-release. Verify blocking with `pg_blocking_pids` as applicable. Fail on barrier timeout. Test gates are absent from release builds. Save client and authoritative row/reservation observations. [PG functions](https://www.postgresql.org/docs/18/functions-info.html) · [Timeouts](https://www.postgresql.org/docs/18/runtime-config-client.html)

| Scenario and forced order | HTTP and authoritative assertions |
| --- | --- |
| P1 Same key/Create across A/B. Hold A after insertion and confirm B waits before releasing A. Repeat with B wait exceeding budget. | A and settled B return 201 with the same ref/status/Location. Timed-out B returns 503 `outcome_unknown`, then same-key retry returns 201. One request, one creation fact, one receipt. Two fresh keys with identical inputs yield two refs and receipts. |
| P2 Same key, different intent. Pause A and issue B with alternate valid inputs on the same key before A commits. Repeat across different routes and with B denied original target. | Authorized B receives 409 `key_conflict`. Concealed B receives ordinary 404 with no key hint. Exactly A’s durable state and one success receipt. |
| P3 Fail A before Create commit and, separately, after Publish reservation and outbox append. B waits for the key, then pauses before effects. | A gets 500. Before B resumes, primary shows no new request or state/revision, receipt, history or outbox. A’s Publish reservation stays burned. B commits once (201 or 200) with one obligation on Publish and a higher ID. |
| P4 Commit succeeds, A loses HTTP response and restarts. Submit original request through B. Test Create and Publish and then expire keys. | Same 201/200 and original ref/ID under grants. Publish test trigger yields one transition and one obligation. At verified expiry, 409 `key_expired`, no writes even after receipt purge. |
| P5 Gate JDBC at commit boundary. In one variant DB commits and proxy drops the acknowledgment after authoritative commit confirmation. In the other the session is ended before backend commit. Hold resolution until A reports uncertainty. | A gets 503 `outcome_unknown` in both variants. B uses original key. Confirmed-commit variant replays and writes zero. Confirmed-abort variant can commit once. While unresolved, lookup-only absence cannot permit effects. An overlapping contender receives 503 at budget. |
| P6 Force both ordering variants of Publish/Reject in ACCEPTED, Edit/Accept in VERIFIED, Verify/Delete in CREATED and Edit/Edit from same observation. | First gets 200, commonly stale loser gets 409 `stale_observation`, no second receipt. Inspect one revision advance and at most one fact. When Edit wins, a newly observed Accept can succeed. Change an assignment/evidence version alone and require stale outcome. |
| P7 Publish across two organizations/types. Gate the first after reserve and confirm the second waits on the namespace. Repeat across rollback and >2^53. | Commit order strictly increases. Original/replay IDs parse exactly as signed 64-bit strings. Exhaustion fails closed. |
| P8 Revoke access before key/request wait ends, and after commit before result release. | Earlier revocation blocks the effect. Later revocation suppresses protected result while the effect remains. Verify no protected body, context, ID or replay hint. |
| P9 Restore an older backup, reuse a revision with different facts, and delay the old writer. For one allowed submitted old-key intent compare a missing receipt with a retained one for a concealed original. | Old token fails. The paired retries have identical 409 headers/problem fields (normalize independent date/correlation), no replay/Location and zero durable writes. Eligible prior replay/conflict still works. Old writer and affected targets stay fenced. First new Create ordinal 1 sorts ahead of older restored rows. New Publish IDs exceed all prior reservations. |

Run P1–P9 on the selected production engine/driver/topology with equivalent observed barriers and failure windows. Include schema upgrade and native backup/failover runs.
