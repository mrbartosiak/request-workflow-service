# Identity, grants and decision context

**Scope** A-05, F-03/08/10, Q-13, R-08, DEC-04/08/11/12. Required zero unauthorized reads or changes. Scoped grants, ordered revocation, masked current disclosure, distinct-person Accept and independent Verify/Publish grants are approved. Exact corporate mappings and this mechanism remain proposed. [HLD](../../../Phase2-HLD/access-and-approvals.md)

`ActorResolver` validates issuer, audience, credential, subject and organization binding. Resolve a stable principal and actor type from the trusted directory. Role and group identifiers are scoped to issuer/organization. An authenticated alias resolves to the existing stable person. Grant rows bind principal/group, organization, type, permission, and any owner, assignment or target predicate. Trusted mapping populates `originatingPersonId` on human Create. Changes to login, delegation, ownership and assignment keep that original person. Initially reject on-behalf-of and service Create until a trusted originating-person mapping is approved. An approved service identity with no resolved human person cannot Accept.

| Permission | Proposed requirement |
| --- | --- |
| `CREATE` | Type and organization grant. Populate owning scope from registered policy. |
| `ROW_READ`, `FIELD_READ(field)` | Use grants and scope predicates to determine detail and visibility. |
| `FIELD_FILTER(field)` | Requires permission to read the filter field as well. Apply per row. |
| `CONTEXT(action)` | Separate action grant and access to all material facts for that action. |
| `EXECUTE(action)` | Check target scope, required context grants and independent action grant. Accept and Reject require individually scoped approval rights. Accept additionally compares stable person IDs. |
| `HISTORY_READ`, `DELETED_METADATA` | Separate history permission and a separate deleted visibility gate. |
| `RESULT_READ(action)` | Current scope, target, action and minimum result fields. Require current action and context grants and `FIELD_READ(publicationId)` for Publish. For a Delete result, require `DELETED_METADATA` and authorize only its minimal receipt fields. |
| Service and operator grants | Explicit sender/tenant/operation scope. Audit operator pause, resume and reconciliation. |

`ActionContextService` returns action and ref, authorized state, and `context` with `body` for Edit, Verify and Accept. Reject, Delete and Publish use state and immutable name as initial decision facts, with Reject, Delete and Publish `context.name`. Accept also returns the policy’s allowed decision facts such as assignment or approved evidence, using explicit type schemas and matching field grants. All actions bind generation, principal, target/type/scope, action, revision, assignment version, policy generation and versions of any required independent facts to an authenticated opaque token. Before a committed new effect, compare those facts and current policy in the same ordered transaction. Unavailable or unauthorized required facts block the action. Self-Accept is denied even with a grant. [REST](rest.md) · [Transaction](persistence.md)

**Proposed local authority.** Every command and visibility-changing write takes the organization `PolicyGuard` exclusively, including Create, Delete, edits, grant/assignment changes, holds and purge. Advance affected context versions. `DisclosureGate` takes it shared in a fresh phase, derives current projections including browse lookahead, and hands off bytes to a bounded outgoing buffer before unlocking. This is release. A prior deletion, purge or revocation governs all fields, tokens and continuation. Earlier release remains valid if bytes arrive later. Conceal deleted context and pre-delete results. Detail gives ordinary 404, or allowed metadata under its distinct grant. Replay errors follow the key contract. Buffer failure leaves receipts recoverable. [Queries](queries.md) · [Retention](retention.md) · [Replay](retries.md)

A verified directory mirror can simplify provisioning. Its evidence must cover signed or trusted source, monotonic revision, gap detection, synchronization watermark, approved maximum staleness and fail-closed outage behavior. A freshness window permits revocation lag. Immediate external revocation needs a proof that directory revocation and local effect/release are ordered. Compare to administering locally ordered grants and treating the local commit as the effective point. Exact roles, person collisions, verified directory outage and service mappings affect these tests. [Decision](decisions.md) · [Access evidence](verification.md)
