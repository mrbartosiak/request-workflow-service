# Identifier allocation and uniqueness boundaries

**Scope** F-01/05, Q-02/03, R-02/09/10, DEC-08/13. Owner constraints are binding. The allocation mechanism and keys below are proposals. [Phase 3 owner requirements](../../owner-identifier-requirements.md)

`initial-requests` is the single Publish namespace for every initial type and organization. Database and allocator uniqueness use `(namespace,id)`. Send decimal strings matching `[1-9][0-9]{0,18}`, with exact signed 64-bit maximum 9,223,372,036,854,775,807. Prohibit truncation and floating-point conversion. Display padding is cosmetic. Preserve existing namespaces and associations in migration and future approved re-publication. Any new namespace needs a permanent disjoint identity and explicit, collision-free reference. Today PUBLISHED remains terminal.

`IdentityAuthority` is linearizable and independently durable outside workflow restore. It stores writer epochs, namespace watermarks and identifier reservations. Enroll every reference issuer. Create reserves a globally unique 32-character base64url string from 192 CSPRNG bits, plus immutable `(createdEpoch,createdOrdinal)`. Both counters are positive signed 64-bit. Each certified writer epoch strictly exceeds every previously issued epoch. Ordinals increase within the epoch from 1. Burn allocations across rollback/restore and block at exhaustion. Expose `ref` after commit and permitted release. Clients retain and transmit it verbatim. [Base64url](https://www.rfc-editor.org/rfc/rfc4648.html#section-5)

## Publish assignment and proof

1. Under the workflow transaction’s current guard and request lock, validate authorization, context and `ACCEPTED`. Acquire exclusive `PublishGate(namespace)` on the single primary shared by all instances, then call the authority with the certified generation and unique attempt ID. It atomically advances its watermark and records `(attemptId,generation,namespace,id,requestRef,operationScopeDigest)`. The same attempt ID resolves only its own allocation uncertainty. A different attempt consumes a different ID. If authority proof is unavailable or the counter would overflow, fail closed without publication.
2. Associate the reserved ID with the request, transition, receipt and approved delivery obligation in the workflow transaction. IDs are assigned at durable successful Publish commit. The gate is held from before reserve through commit/rollback, and a subsequent publisher can acquire it only after that transaction ends. Therefore completed commits assign IDs in strictly increasing order across different requests, independent of request arrival, response arrival or instance. Rollback burns the reservation. Attempt ambiguity is resolved by same-key arbitration and explicit recovery proof before a fresh allocation for that target. Authorized replay reads the same durable ID without allocation.
3. Recovery physically excludes all older workflow writers before activating a new authority generation. Snapshot B had IDs through 40. After B, IDs 41 and 43 were published and 42 burned on rollback. The authority survives at 43. Restoring B cannot reserve 41–43. Determine and recover the missing associations or fence their targets using reservations and authoritative workflow history. The first new allocation is 44, including after migration. Without independent authority, verified prior association or safe target classification, block affected publishing. [Recovery](recovery.md)

The global gate and synchronous authority call add wait and dependency costs. Alternative externally reserved disjoint ranges amortize round trips and can meet the same guarantee only with serial commit order, safe range retirement across old writers and proof of affected assignments. Compare cost and fault modes before selection. A rewindable database sequence alone cannot prove recovery safety. [PostgreSQL sequences](https://www.postgresql.org/docs/18/functions-sequence.html)

## External mappings

`ExternalMapping` has immutable key `(sourceSystem,tenant,identifierType,externalId)` and value `(localKind,localRef or namespace plus numeric ID)`, all scope-validated. An external ID is compared within its type and tenant. Propose an independently durable reservation of the exact mapping, followed by the local committed projection before business use. Compare equal mappings for replay. Quarantine conflicts pending reconciliation. Retain dangling reservations until authoritative proof resolves them. Rebuild committed associations from verified records. Block scoped keys when commit or identity is uncertain. A mapping migration verifies equality of every previous scoped key and value and never recycles entries. [Integration](integration.md) · [Restore checks](recovery.md)
