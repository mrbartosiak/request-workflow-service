# Java and Spring assembly

**Scope** A-02/03/04/06, F-08–11, Q-07–09, DEC-03/04/06/08/10/14. Java 25, Spring Framework 7.0.11, composition and a single deployable release with separate modules are approved. Module names and pinned dependencies beyond the baseline are proposed. [Java 25](https://docs.oracle.com/en/java/javase/25/docs/api/) · [Spring release](https://github.com/spring-projects/spring-framework/releases/tag/v7.0.11) · [HLD](../../../Phase2-HLD/architecture.md)

Root package `com.company.requests`. Separate build modules enforce permitted dependencies. Ports expose application or domain value types. Spring and vendor types remain in adapters.

| Module / package | Owns | Permitted project dependencies |
| --- | --- | --- |
| `domain` | `Request`, value types, `Lifecycle`, `TransitionFact`, `WorkflowPolicy` | none |
| `application` | Command/query/context services, `DisclosureGate`, `IdentityAuthority`, storage/transaction ports, `OutboxAppendPort` and `OutboundObligation` | domain |
| `adapter.http` | Spring MVC controllers, DTOs, validators, Problem Details mapping, security chain and `ActorResolver` implementation | application, domain |
| `adapter.jdbc` | SQL record mapping, receipt arbitration, grant/query repositories and `TransactionRunner` implementation | application, domain |
| `adapter.authority` | Certified generation, durable identity/mapping authority client and witness client | application, domain |
| `integration` | `DispatchCoordinator`, `InboundGateway`, `VendorConnector` and delivery ports, bounded scheduling | application, domain |
| `adapter.integration.jdbc`, `adapter.vendor` | Delivery SQL and vendor HTTP/mapping adapters with fakes for the same contracts | integration, application, domain |
| `profile` | Composed request-type `WorkflowPolicy` implementations and configured grant/evidence rules | domain, application |
| `bootstrap` | Explicit `@Configuration` and `@Bean` wiring, validated settings, independent pools and release readiness gates | all |

Use Spring MVC, `ProblemDetail`, `JdbcClient`/`JdbcTemplate`, and `TransactionTemplate` with a `JdbcTransactionManager`. Bound deadlines and classify commit ambiguity by execution phase. Use `TaskScheduler` plus separate bounded worker pools, and bounded Spring `RestClient` for vendor I/O. Annotation-driven transactions would need explicit proxy and commit classification checks. [Transactions](https://docs.spring.io/spring-framework/reference/7.0/data-access/transaction/programmatic.html) · [JDBC](https://docs.spring.io/spring-framework/reference/7.0/data-access/jdbc/core.html) · [REST client](https://docs.spring.io/spring-framework/reference/7.0/integration/rest-clients.html) · [Errors](https://docs.spring.io/spring-framework/reference/7.0/web/webmvc/mvc-ann-rest-exceptions.html)

**Atomic append.** `application.OutboxAppendPort.append(OutboundObligation)` is implemented by `adapter.jdbc.JdbcOutboxAppender`. `CommandCoordinator` invokes it inside `TransactionRunner` using the workflow `commandTxManager` and `commandDataSource`. The appender joins that same Spring-bound JDBC connection and transaction. `adapter.integration.jdbc` reads committed obligations and uses `workerTxManager` and `workerDataSource` for claims/finalization in the same schema. The worker module depends inward on contracts and needs no dependency on `adapter.jdbc`. Verify by compiling permitted module edges and injecting rollback after the append. [Records](persistence.md) · [P3](postgres-evidence.md)

**Dependency decisions.** Propose Spring Security resource-server support if the approved identity source is JWT/OAuth2. It supplies standard authentication and token validation at the servlet boundary. Project access policy remains in application code. Cost includes separate advisory tracking and issuer configuration. Custom token filters increase security review work. Verify selected issuer, dependencies, Java 25, Spring 7.0.11 and clock/revocation behavior. Select a compatible Servlet runtime, JSON provider, JDBC driver and production connection pools against the release matrix. These supply the transport, parser and engine wire protocol through interfaces Spring consumes. Explicit wiring and engine-native pool/driver are alternatives to introducing an ORM or extra stack. pgJDBC is only the PostgreSQL proof driver. Use Spring Test/JUnit for fast and HTTP contract fixtures. Against real PostgreSQL an approved external test instance avoids adding a container-test library. Pin versions and record transitive advisories before adoption. Additional build tools are evaluated separately.
