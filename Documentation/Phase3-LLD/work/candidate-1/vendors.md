# Corporate integration assessments

**Scope** A-06, F-11, Q-08/09, DEC-03/09/10. Phase 2 assessments carried forward. Proposed flows and measures are candidates. Live product, priority, triggers, entitlements and privacy approval remain open for all five. [Signed HLD vendor assessment](../../../Phase2-HLD/vendor-assessment.md) · [Owner kickoff](../../owner-kickoff.md)

| Vendor | Proposed value and evidence | Ease, prerequisites and boundaries |
| --- | --- | --- |
| Workday | Minimal worker reference and approved org attribute for HR routing. Measure wrong queues and manual reassignments. | Scoped lookup, cache freshness or periodic refresh, manual route fallback. Confirm tenant, Staffing version, permitted security domains, fields and mapping. [Workday guide](https://developer.workday.com/documentation/GUID-6c547385-848b-4005-ab2c-632f1d6b5688) |
| Atlassian Jira | Bug handoff with safe summary and correlation. Store the scoped issue link. Measure missing/duplicate handoffs and manual steps. | Confirm Cloud vs Data Center, project grants and safe write proof. Cloud search can lag, and stronger reconciliation using a known issue ID cannot prove absence after an ambiguous create with no ID. Keep status import separate. [Issues](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/) · [Search](https://developer.atlassian.com/cloud/jira/platform/search-and-reconcile/) · [Rate limits](https://developer.atlassian.com/cloud/jira/platform/rate-limiting/) |
| ShiftLeft | Link scan and finding references, approved severity and revision to remediation or exceptions. Measure time to link and dedupe stability. | Confirm actual product/version and stable finding IDs, token scopes, retention and reconciliation read. Carry forward the Qwiet/Harness product identification question. [Qwiet API](https://docs.shiftleft.io/sast/api/walkthrough) · [Harness product transition](https://www.harness.io/blog/qwiet-ai-is-now-harness-sast-and-sca) |
| SonarQube | Attach gate evidence scoped to project, branch and revision. Measure evidence verification time and stale matches. | Server documents signed webhook support. Confirm Server vs Cloud and version, credentials and analysis identity. Treat callbacks as hints pending authoritative validation of scope and supersession. [Webhooks](https://docs.sonarsource.com/sonarqube-server/discovering/integrations/webhooks) · [Web API](https://docs.sonarsource.com/sonarqube-server/extension-guide/web-api) |
| Sonatype | Lifecycle report, component and policy evidence for exceptions. Nexus Repository artifact references are a separate read flow. Measure linking time and stale results. | Confirm product, permissions, retention and overlap with ShiftLeft. Lifecycle documents no retry for failed webhook deliveries. Prove completeness through confirmed reports, audit or reconciliation. [Lifecycle webhooks](https://help.sonatype.com/en/lifecycle-webhooks.html) · [Report API](https://help.sonatype.com/en/report-rest-api.html) · [Nexus search](https://help.sonatype.com/en/search-api.html) |

Before any live connector decision require tenant-specific sample payloads, documented stable identities, read/write scopes, network credentials, accepted failure and revocation semantics, authoritative reconciliation, operating owner and approved data flows. Evaluate sandbox with production-like controls only after approval. Fake fixtures establish core conformance independently of these prerequisites.
