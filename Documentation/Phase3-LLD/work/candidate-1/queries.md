# Browse and masked history

**Scope** F-06/07/08, Q-11/12/13, R-08, DEC-01/04/05/11. **Required** Exact case-sensitive name, exact current state, default page 10, complete ordered history and authorized masking. Wire and retention settings are proposed as indicated. [HLD browsing](../../../Phase2-HLD/browse-contract.md) · [HLD history](../../../Phase2-HLD/workflow-and-history.md)

`RequestQueryService` returns the first `size` authorized matches in descending `(createdEpoch, createdOrdinal, ref)` order. Compare the immutable positive 64-bit epoch and ordinal numerically and the stable `ref` tie-breaker by unsigned UTF-8 byte order. Use the same comparators for the exclusive less-than bound from the last returned item. Failover advances the epoch even when the ordinal restarts. Validate name with the Create name contract and compare the original UTF-8 bytes. Validate state as one of six lifecycle states and combine supplied filters with AND. Empty matches yield `{items:[]}`. `size` is optional, default 10, bounded 1–50. Items are `{ref,type?,name?,state?,publicationId?}` under independent read permissions. [Ordering source](identifiers.md)

1. Authenticate and validate page parameters, token bounds and signature. Establish organization scope and effective policy.
2. Under the shared organization guard in the release phase, read the authorized relation from authoritative storage. Filter first on row access, retention and permission to query every supplied field. Apply exact filters and the exclusive bound within that relation. A denied value contributes nothing to results or continuation.
3. Fetch `size+1` under the same guard. The extra row must be currently visible and match through release. Include `nextCursor` only when that row exists and tie it to the last returned item. Omit counts and mask fields per row. Hand off the whole page before unlocking, so deletion, purge, policy and other visibility writes cannot interleave between selection (including lookahead) and release.
4. Recompute permissions and live membership on each request. New rows above the exclusive bound do not appear in this sweep. State or grant changes can move a row into or out of later pages. An unchanged eligible set traverses once in fixed order.

Proposed opaque encrypted, authenticated cursor ≤2,048 ASCII bytes with key ID, principal/organization, normalized filter tuple (exact text and enum), size, order version, recovery generation, last tuple, expiry. Default lifetime 15 minutes, bound to current trusted time. On continuation, resend equal effective filters and size. Reject invalid, mismatched or expired input uniformly with 400 and restart the browse. A new generation invalidates earlier cursors. The token grants no access. Compare this to offsets, which shift under mutations, and snapshot paging, which requires retention and still needs live permissions. [Access](access.md) · [Recovery](recovery.md)

`HistoryQueryService` requires `HISTORY_READ`, row visibility and permitted state-history facts. Denial of the distinct grant yields no history. An authorized initial response includes only `sequence,action,from,to` ordered by `sequence ASC`. Creation `from` is JSON null. Omit actor, reason, body and timestamp. The initial lifecycle has at most four state changes. Authorized `DELETED` access permits `ref,type?,state?` and separately authorized masked history. Exclude deleted names from name matching and suppress deleted payload on public surfaces. Preserve lifecycle facts across purge, replay and restore.
