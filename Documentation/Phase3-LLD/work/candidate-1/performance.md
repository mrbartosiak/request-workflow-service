# Performance smoke and acceptance

**Scope** Q-01, R-03, DEC-07. The owner authorized a quick opt-in check. Proposed profile and evidence below are **planned, unrun**. The workspace is design-only as observed during drafting. Candidate development provides no test throughput measurement. [Owner kickoff](../../owner-kickoff.md) · [HLD performance plan](../../../Phase2-HLD/performance-test-plan.md)

**Quick check.** Use a runnable built candidate on Java 25/Spring 7.0.11, two application instances, one shared real database and the independently durable identifier authority. Keep configured authentication, disclosure, witness and logging in path. Use synthetic grants, preloaded requests and pre-issued keys plus action observations. Reserve distinct eligible targets for each write. Prepare >10 visible browse matches. No live vendor calls. Record instance resources and actual worker/authority conditions. Perform 10 s warm-up and 30 s measurement at 100 independently scheduled core requests/s, balanced across instances, with round-robin Create, Edit, Verify, Accept, Reject, Delete, Publish and Browse. Submit 375 offers per operation in the measurement interval. Report preflight context/key work separately as outside this smoke’s timed mix. Each client request starts timing at its scheduled arrival, even when generator/client queues delay send. Continue recording to response or configured timeout. Keep every offer in the denominator, including any unstarted or unreturned. Check sample durable records plus offered/completed counts and all per-operation statuses.

A valid quick run gives a timing signal for the measured workload only. Its profile uses prepared keys and observations, no hot targets and a small data set. Report version, backend, clocks, fixture size, resources, warm-up, split by instance, and eligible successes, conflicts, unexpected statuses, missing/timeouts, max and p50/p95/p99 plus ≤500 ms count and share for each operation. Include total offered/completed count and sampled durable results. Attach sanitized raw timing and logs. Report observed results when an executable environment exists.

**Required acceptance remains** 100 sustained requests per second across at least two service instances. Every measured request completes strictly under 3 s, and ≥95% of each core operation completes within 500 ms under the agreed workload. A timeout, missing response or ≥3 s value fails the per-request threshold. Verify valid throughput at offered load as well as latency. Approve the full data distribution, action/key prep mix, skew, warm-up/duration, resources and response/error denominator before acceptance. Pace open-loop and report dependency impairment, retries, contention or delivery load separately from a normal-load baseline. Keep performance execution out of CI and routine builds.
