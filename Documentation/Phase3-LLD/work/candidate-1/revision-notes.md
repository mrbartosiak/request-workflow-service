# Candidate 1 response to review

**Revision** PH3-C1-r2. **Scope** Changes requested by Reviewer 1 on PH3-C1-r1. These are design changes with planned observable checks. [Review](../reviews/candidate-1-r1-review.md) · [Manifest](manifest.md)

| Finding | Change | Acceptance check |
| --- | --- | --- |
| 1. Delete/purge vs release | Every visibility write takes the organization guard exclusively. Authorization, final projection and output handoff hold it shared. Include the page lookahead. Detail, context and replay obey current deletion/retention. [Access](access.md) · [Transactions](persistence.md) · [Queries](queries.md) | E3/E4 force both orders for deletion, page continuation and purge. Earlier Delete yields only authorized metadata or absence, no body/token, and no cursor when it removes the only lookahead. [Evidence](verification.md) |
| 2. Restored-key concealment | For allowed submitted intent an old missing, untrusted or concealed receipt uses uniform 409 `retry_fenced`. Eligible prior replay and authorized conflict remain. [Retries](retries.md) | P9 compares status, headers, problem fields and zero durable effects in both old-key histories. [Evidence](postgres-evidence.md) |
| 3. Scoped delivery identities | Attempt PK/FK spans the full effect identity. Inbox uses a trusted identity domain and compares declared type as content. [Delivery](integration.md) | E6 tests a colliding effect ID across destinations and changed declared event type under one tenant-level event ID. [Evidence](verification.md) |
| 4. Atomic append wiring | Application owns `OutboxAppendPort` and `OutboundObligation`. `JdbcOutboxAppender` shares the command transaction and connection. Dispatcher uses a different pool/transaction, through inward dependencies. [Assembly](wiring.md) | P3 fails after append and compares request, receipt, history and obligation before the retry proceeds. Check module graph at compile. [Evidence](postgres-evidence.md) |
| 5. Creation order across restores | The independent authority increments a positive numeric writer epoch across failover. The per-epoch numeric ordinal starts at one. Old tuples and comparison remain immutable. [Identifiers](identifiers.md) · [Queries](queries.md) | E3/P9 assert that the first new ordinal after old-backup restoration precedes all older rows. [Browse evidence](verification.md) · [PostgreSQL evidence](postgres-evidence.md) |
| 6. Payload retention alternatives | Compare timed protected history to terminal minimization, with explicit permissions, holds, purge and old-backup consequences. Keep lifecycle facts in both. Payload policy and authority await approval. [Alternatives](retention.md) · [Decisions](decisions.md) | E7 exercises holds in both orders, logical purge before failed cleanup and restoration of ciphertext with a later ledger decision. [Retention evidence](retention.md) |

The proposed organization guard trades concurrency within an organization for a reviewable release order. Its cost at load remains unmeasured. Production engine, owner choices and all runtime evidence remain open. [Performance](performance.md) · [Choices](decisions.md)
