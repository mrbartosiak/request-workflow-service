# Browse and history

**Scope** F-06/07, Q-11/12/13, DEC-01/04/05/11. **Status** Match, sort, page style, default size and history mask are approved. Proposed details and delegated limits are identified below. [HLD browse](../../../Phase2-HLD/browse-contract.md)

`ReadService.browse` takes an authenticated directory scope. Proposed input names are `name`, `state`, `limit` and `cursor`. Default limit is 10. Delegated max is 100, min 1 and cursor life 15 minutes. Match the exact stored name's UTF-8 bytes with case and whitespace preserved. Match the current state by exact code. Combine supplied filters with AND. Use the immutable creation-order key descending and opaque ref as a unique descending tie-breaker, with bytewise ref comparison. [Entry validation](rest.md) · [Creation order](identifiers.md)

The authoritative browse query under the scope gate first creates an authorized row relation, including retention visibility. Project allowed exact-name and state filter values into that relation and omit each row when a supplied filter is forbidden on that row. Apply exact match and keyset predicate to that relation, then order and take limit+1. The PostgreSQL reference may use a materialized CTE to establish the boundary. Output projections are independently masked. Authorization inputs and retention visibility hold through final release. No hidden row or protected filter value contributes to page selection, `hasMore` or cursor. Query plan optimizations require equivalent adversarial tests. [Access](access.md)

`BrowsePage` returns `items` (ref and separately allowed name, state, type and publicationId) and `nextCursor` only when an extra match exists. Empty pages contain no cursor. Do not expose a count. `CursorCodec` authenticates and encrypts issuer, organization, principal, effective scope, writer generation, ordering version, validated filter values, page size, expiry, and the last emitted sort tuple. Continuations repeat the same filters and effective limit. Reject mismatched, expired or invalid cursor with INVALID_CURSOR. A cursor grants no data privileges. Reauthorize and build a new page on the current dataset each time. State or grants may change membership, and newer rows can fall behind the caller's traversal boundary. Fixed visible membership follows stable order. [Access](access.md) · [Recovery](recovery.md)

`ReadService.history` requires target visibility and a separate history grant. `HistoryView` returns `ref` and ordered `changes`. Each item contains ordinal, from (null at creation) and to. Exclude actor, reason, timestamps, body and approval evidence from the initial wire. Denied targets return safe concealment, authorized deleted markers may retain masked history. Database records remain complete regardless of reason/body purge. Lifecycle size is bounded by the initial workflow. Future approved variants can revisit pagination without discarding facts. [Domain](domain.md) · [Retention](retention.md)

**Alternatives** Offset shifts under changing data and snapshot cursors require stored membership plus live permission checks. Textual byte equality fits the approved case-sensitive semantics while avoiding dependence on a locale collation. Test independent/combined filters, Unicode normalization differences, default 10, tied order tuples, cross-scope cursors, revoked visibility, and changing hidden values with identical page contents/cursor behavior.
