# Tooling decisions

**Scope** A-02/03, Q-04/07/08, DEC-06/10/14. **Status** Candidate recommendations. Adoption, version and artifact pinning require owner approval where material. Ensure a clean build using Java 25 and Spring Framework 7.0.11. [Owner tooling requirements](../../../output/Assumptions-initial-HumanMade.txt)

| Option | Source and checkpoint | Benefit, alternative, cost and candidate recommendation |
| --- | --- | --- |
| YAML/OpenAPI DTO generation | Reviewed OpenAPI YAML is public wire truth. Reproducible model-only generation in build if adopted, with CI diff of clean outputs. | OpenAPI Generator's Spring generator can derive models; defaults are oriented to Spring Boot. Use handwritten MVC records with wire fixtures first. Defer model generation pending compile, annotation/Jackson compatibility, 64-bit string, optional fields and clean boundary proofs. Adds template/version maintenance. [Spring generator](https://openapi-generator.tech/docs/generators/spring/) |
| Compile-time DTO mapping | Wire records and core command/result contracts. Annotation processing in compile if adopted. | MapStruct generates mapper implementations during build. Prefer explicit Java for access-aware field projection and small DTO sets. Defer until mechanical volume justifies processor maintenance; require unmapped-field failure, field-mask tests and Java 25 build proof. [MapStruct](https://mapstruct.org/documentation/stable/reference/html/) |
| Breaking API changes in CI | Compare candidate YAML with immutable latest approved released spec at PR/release. | Recommend a pinned `oasdiff breaking` CI pilot plus running Spring MVC contract fixtures. Faster structural detection than manual diff, still needs behavioral verification for masks/errors/layout. Prove a seeded break fails, an allowed additive change passes, and exact version/rules/baseline reproduced in CI. No app runtime cost. [oasdiff](https://www.oasdiff.com/docs/getting-started) |
| Database-schema-derived types | Applied approved migration set + chosen database/version. Build integration profile migrates isolated schema before generation. | jOOQ can derive typed table/record APIs and catch stale column references. Prefer Spring JdbcTemplate + explicit mappers and migration queries now. Defer until engine chosen and schema size justifies tool/runtime, edition/licensing and deterministic generation costs. Prove removal breaks build and rollback remains compatible. [jOOQ](https://www.jooq.org/doc/latest/manual/code-generation/) |
| Schema-derived event payloads | Versioned owned event schema for public contract. CI compatibility + fixture decode and clean generation before deployment. | Apache Avro can generate Java types from schemas. Use manually mapped, versioned minimal delivery envelopes and fixture round-trip initially. Defer new schema tooling until multi-consumer compatibility warrants runtime/build/registry costs. Require old/new reader tests, unknown-version handling, field masking and retention proof. [Avro](https://avro.apache.org/docs/1.12.0/getting-started-java/) |
| Package-boundary tests | [Allowed dependencies](spring.md). Run compiled package and cycle checks in PR, release and migration branches. | Recommend test-only ArchUnit after Java 25 compiled class import and violation fixtures pass. Gradle/Maven modules and JDK jdeps are lean alternatives; module edges alone miss prohibited same-module package use. Prove negative fixtures for core→Spring and provider→controller, cycles and correct wiring. Costs include dependency review and matching rule upkeep. [ArchUnit](https://www.archunit.org/userguide/html/000_Index.html) · [JDK jdeps](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jdeps.html) |

Qualifying tests pin the tool/version and fixture set. Record tool failure boundaries, run time, maintenance owner and reviewed artifact locations before production adoption. Leave generated and provider types outside core and do not ship test dependencies in the runtime distribution. CI shape checks and package tests supplement authorization, compatibility and durability tests. [Operations](operations.md)
