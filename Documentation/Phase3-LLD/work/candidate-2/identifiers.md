# Identifiers and publication order

**Scope** F-01/05/09, Q-02/03/10, R-02/09/10, DEC-03/08/13. **Status** Phase 3 owner requirements bind. Allocation mechanisms below are proposed. [Owner requirements](../../owner-identifier-requirements.md)

**Create reference.** `CreateReferenceAllocator` locks the active `global_creation` counter through commit. Pair the positive ordinal with the globally non-repeating writer generation for lexicographic creation order. Proposed opaque encoding uses the fixed 128-bit pair, an AES single-block permutation with a dedicated key and unpadded base64url. Key changes use a disjoint opaque prefix from a permanent format/key registry. Enforce global ref uniqueness. Clients must never parse or construct the value. A provisional ref stays inside the Create transaction. No response, independently persisted association, external map/reservation, dispatch or telemetry can disclose it before a known durable Create commit. A rolled-back ordinal can therefore be reused without rebinding any released reference. Exclude committed refs after loss with the new generation. Stop before exhaustion. [AES specification](https://csrc.nist.gov/pubs/fips/197/final) · [Recovery](recovery.md)

**Publish ID.** Initial namespace `enterprise-requests` spans every organization and all initial types served by the system. Namespace identity is stable through storage moves. `PublicationId` wraps a positive Java `long` through 9223372036854775807. Serialize as canonical digits in a JSON string, with no leading zero for the wire form. Presentation padding is optional. No float, width-based truncation, coercion or JavaScript number conversion. [REST](rest.md) · [JSON numbers](https://datatracker.ietf.org/doc/html/rfc8259#section-6)

**Assignment proof.** An eligible Publish locks the namespace's single local `publish_serial` row through local commit/rollback. Under the lock the independent journal advances high-water and persists a ref-bound reservation before issuing its number. It rejects closed or unproved writer generations and fences unresolved ref assignments. For two successful assignments in one generation, A, holding the lock first, reserves and commits before B reserves. B's ID is greater and B commits after A. High-water survives hard-fenced writer changes. Reservation failures and aborts can burn IDs. HTTP responses may arrive in another order. Exact replay and any future approved re-publication keep the original ID. [Publication journal](publication-reconciliation.md) · [Transactions](transactions.md)

A different design reserves durable contiguous ranges outside restore, one active range/cursor per namespace and writer generation, with serialization through commit and a non-rollback local cursor. Burn all uncertain/old ranges upon writer change. This avoids a synchronous allocator call on each Publish but increases fencing, exhaustion and concurrency proof work. A plain local sequence cannot alone prove commit order or survive rollback of the store. [PostgreSQL sequence behavior](https://www.postgresql.org/docs/18/functions-sequence.html)

**External mappings.** `MappingRegistry` durably binds exact (source system, source tenant, identifier type, external ID bytes) to the immutable ref and applicable original namespace and ID. A separate post-Create mapping operation must first prove the current target's committed ref. A mapping with a publication ID also verifies the confirmed publication association. The independent registry reserves before local mapping insertion. Equal associations can be reconciled. Conflicting remaps fail and quarantine. Reservation survives unsuccessful local insertion. Restore a local mapping only with verified target, commitment and authority. Otherwise isolate the association without reassignment. Preserve registry, formats and namespaces across migration. New namespaces require approved collision and compatibility proof. [Data records](records.md) · [Recovery](recovery.md)
