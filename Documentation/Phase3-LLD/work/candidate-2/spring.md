# Java 25 and Spring Framework 7.0.11

**Scope** A-01/02/03/04, F-08–11, Q-07/08/09, DEC-03/08/10. **Status** Runtime baseline and composed one-release packaging approved. Modules and concrete classes are proposed. [HLD architecture](../../../Phase2-HLD/architecture.md)

| Build module and package root | Owned responsibilities and allowed dependency |
| --- | --- |
| request-core · `request.core.domain` / `request.core.application` / `request.core.spi` | Domain records and WorkflowRules. CommandService, ReadService, ReceiptService and auth decisions through port interfaces. JDK-only. Transaction and release coordination exposed as application-owned ports. No infrastructure imports. |
| request-web · `request.web` | RequestController, CommandKeyController, EarlyRequestValidator, ActorResolver adapter, ResponseReleaseAdapter and ApiErrorAdvice. Depends on core and Spring MVC/security/JSON. No storage or delivery imports. |
| request-storage · `request.storage.jdbc` | WriterAdmissionAdapter, JdbcCommandTransaction, JdbcReadReleaseTransaction, JdbcRequestStore, JdbcReceiptStore and typed row mappers. Depends on core and Spring JDBC/tx. PostgreSQL-specific statements isolated here. |
| request-delivery · `request.delivery` | DeliveryIntentFactory adapter, DispatchClaimService, DispatchAuthorizationService, DispatchWorker, InboundService, connector SPI and fake. Worker transactions use separate claim/authorize/finalize boundaries. Depends on core ports and Spring infrastructure. Provider packages stay behind connector SPI. |
| request-runtime · `request.runtime` | Explicit bean assembly, identity provider and independent-authority clients, deployment and operational instrumentation. Depends on all concrete modules. Singleton policies, per-request trusted actor and no mutable per-request shared bean state. |

Use Spring MVC annotated controllers and `@RestControllerAdvice`, bounded body reader and pinned JSON converter. A security filter verifies credentials before controller input parsing. Use Spring Security if approved for corporate token verification and filter integration, selected with its compatibility matrix and issuer validation tests. A manual Servlet authentication filter is the alternative and would own signature, issuer, audience, expiry and rotation checks. Use explicit Java record DTOs and pure mapper functions selected by scope. No ORM or generic resource controller. [Spring MVC validation](https://docs.spring.io/spring-framework/reference/7.0/web/webmvc/mvc-controller/ann-validation.html) · [REST](rest.md) · [Tooling](tooling.md)

Use `TransactionTemplate` over `JdbcTransactionManager` and parameter-bound `JdbcTemplate`. Return a planned result from the transaction port. Release follows known commit, required outside confirmations and fresh authorization. A gate-held disclosure transaction uses locking, bounded serialization and release. Map rollback and unknown to typed outcomes. Give delivery dedicated Spring schedulers, executors and pools. Wire through named `@Configuration` beans. Use bounded clients for `PublicationJournal` and `ScopeAuthorityJournal`. Verify settings, migrations, schema/codec compatibility, time and proof before readiness. [Spring transactions](https://docs.spring.io/spring-framework/reference/7.0/data-access/transaction/programmatic.html) · [Spring JDBC](https://docs.spring.io/spring-framework/reference/7.0/data-access/jdbc/core.html)

**Dependency proposals** A Servlet engine and JSON provider supply standard HTTP/JSON integration. Pin compatible versions and verify Unicode, decoding bounds, duplicate input and tail behavior. Manual HTTP/JSON implementations add parser and lifecycle risk. JDBC requires the approved engine driver and production DataSource. Prefer a bounded platform-managed pool over direct DriverManager connections per request. Dedicated pool library needs leak, limit and timeout evidence if platform pooling is unavailable. Add a migration runner only when engine selection and schema rollout proof justify it. Unit/contract tests can use the build's test framework and external PostgreSQL setup, avoiding a mandatory container runner. [Tooling](tooling.md) · [Evidence](postgresql-evidence.md)
