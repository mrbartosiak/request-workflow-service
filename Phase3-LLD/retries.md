# Operation keys, retries and retention

**Scope** A-04, F-01/05/08/09, Q-02/03/13, R-01/08/10, DEC-04/05/08. D1-R adopts signed expiring keys and trusted replay. Operational wait and proof-call budgets are reference proposals. [HLD](../Phase2-HLD/retries-and-failure-timing.md)

`OperationKeyIssuer` returns a signed opaque key carrying random token ID, issuer, organization, stable principal, issued time, absolute expiry and active command generation. Scope survives role changes and applies across routes. Compare only after signature, claims and trusted-clock proof. Use a 24-hour reference validity. Propose a 3-second effect-admission margin and deny new execution if authority or clock proof is unavailable. `IntentDigest` uses a versioned keyed digest over a length-delimited typed tuple of action, target (or Create type), original exact decoded inputs and the exact original observation token. Use purpose-specific keys and preserve derivation versions until supported comparisons expire. Replay means equality of this tuple, independent of JSON member order or transport metadata.

Authenticate, validate and prove submitted access/current authority. Verify signature, scope and expiry before receipt lookup. An active key claims its unique row using `INSERT ... ON CONFLICT DO NOTHING` in PostgreSQL. After contention read in a fresh statement under the guard, checking time and authority again first. Commit a tentative receipt with effects or roll it back. Past-generation unexpired keys use authoritative lookup only. Before replay or conflict release recheck time and access to both intents. Expiry supersedes a prepared prior outcome. Conceal inaccessible original outcomes for active keys. [Database insert](https://www.postgresql.org/docs/18/sql-insert.html) · [Access](access.md)

| Condition after access checks | Client result and durable effect |
| --- | --- |
| Active key and no retained row after authoritative arbitration | New action if within effect margin. For an existing request, check observation and workflow. Create has no observation. Commit once or roll back the claim. |
| Matching successful receipt within lifetime | Original status and facts under current disclosure. Publish requires confirmed original association. Ignore historical workflow eligibility. |
| Retained receipt and changed intent | 409 `key_conflict` when both sides are currently disclosable. Zero effects. |
| Verified expired key | 409 `key_expired` uniformly from the signed cutoff after submitted-intent access. Do not look up a receipt. Zero effects. |
| Earlier generation, receipt missing, untrusted or concealed | For the same disclosable submitted intent, always 409 `retry_fenced` with the same problem fields and header policy, including no Location, replay marker or prior details. Correlation is unrelated to receipt presence. No writes. An eligible matching receipt or a fully authorized conflict still uses its ordinary outcome. |
| Wait budget exceeded or uncertain commit | 503 `outcome_unknown`. No claim about prior commit. Retry same original intent/key with jitter. |
| Proven pre-commit rollback | No success receipt. Same key may proceed within the active window after fresh checks. |

Resolve on trusted lineage by settling the key or proving the original effect. Unproved absence admits no new effects. Unready scope returns ordinary authority deferral before receipt lookup. An audited resolver can confirm while public access stays closed. With current scope and missing publication proof use 503 `outcome_unknown`. Same-key resolution may update exact proof/projection and release evidence, with zero second business effects. Proposed budget 2.4 s, pool ≤100 ms, lock ≤200 ms each/400 ms total, proof ≤150 ms per call, capped statements and release margin. Retry a proven transient rollback at most once with the original budget. Reconcile expired uncertainty before a fresh key. [Resolver](proof-resolution.md) · [Recovery](recovery.md)

**Receipt retention.** The selected signed expiry protocol costs a preflight call and bounds replay. The unselected UUID alternative needs durable retirement markers or proof of scope closure. Set reference receipt cleanup at 24 h after expiry, using trusted time, then enforce signed expiry alone. Retain trusted validation keys or retired epoch cutoffs.
