# Tooling evaluation

**Scope** Owner LLD options A/B/C/D/F/H, A-02/03, Q-04/07/08, DEC-06/08/10/14. The owner selected all six R choices. T3-R and T6-R authorize pilots only. Exact pins, mandatory gates and material dependency adoption require compatibility and reviewed results. [Owner assumptions](../output/Assumptions-initial-HumanMade.txt)

| Choice | Source, check and comparison | Decision and evidence |
| --- | --- | --- |
| T1-R · YAML/OpenAPI DTOs | Versioned OpenAPI YAML owns public shape. Spring MVC controllers and validation own behavior. OpenAPI Generator’s Spring generator targets a Spring Boot server layout. Models-only generation might reduce duplicated DTOs, but verify JSON module, annotations, templates and runtime assumptions. Manual Java records and Spring contract tests are simpler with few routes, and require spec/DTO drift checks. | **Use explicit Java DTOs.** Generation stays deferred. CI validates the spec and exercises JSON against approved examples. Before adoption show reproducible models-only output compiling on pinned stack with null/omitted distinctions, strict text, masks and decimal-string IDs. [OpenAPI spec](https://spec.openapis.org/oas/v3.1.2.html) · [Generator](https://openapi-generator.tech/docs/generators/spring/) |
| T2-R · DTO mapping | Java boundary DTO and explicit permitted projection types are authoritative. MapStruct uses annotation processing and configurable unmapped-field policies. It reduces mechanical mapping and adds processor setup, generated diff and compiler compatibility. Manual constructors keep tiny maps and required masks reviewable. | **Use handwritten maps.** CI compiles and tests them. Reconsider after repetitive DTO growth. Prove pinned Java 25 processor, error on missing output, sensitive projection exclusion and supported nulls. Keep permission policy explicit. [MapStruct guide](https://mapstruct.org/documentation/stable/reference/html/) |
| T3-R · API diff | At pull request and release, pilot pinned oasdiff in CI against the last approved released OpenAPI spec, paired with Spring behavior tests. Use a seeded OpenAPI fixture only for pilot evidence before a released baseline exists. Manual spec diff with MVC tests takes more review effort. | **Pilot approved.** Verify route removal and ID string-to-number fail the diff and safe additions pass. Keep role/mask behavior tests. A mandatory gate needs the approved released baseline, compatible pin and reviewed results. [oasdiff](https://github.com/oasdiff/oasdiff) |
| T4-R · Schema-derived types | Selected engine migrations are authoritative. jOOQ can generate Java schema representations. Generate against a disposable migrated database before compile in CI, avoiding shared schema introspection. Cost includes dialect, licence/edition, generator and database reproducibility. Spring JDBC explicit row maps plus engine tests provide a smaller initial stack. | **Use explicit Spring JDBC maps.** Generation stays deferred. Before reconsideration prove engine/licence, Java 25 and type fidelity for decimal-string boundary, uniqueness and secure payloads on both fresh/upgrade migration. Generated types do not prove transaction behavior. [jOOQ generator](https://www.jooq.org/doc/latest/manual/code-generation/) |
| T5-R · Event envelopes | Versioned event schema plus version registry is authoritative if consumers and transport are selected. Avro defines schema resolution and Java generated records. It introduces codec/build and compatibility tooling. Initially use explicit versioned internal obligation DTOs and Spring/JDK serialization tests with fixture schemas. | **Use explicit versioned envelopes.** CI checks old/new payloads and strict field allowlists. Reconsider when multiple external consumers need compatibility. Prove replay of retained old records, supported reader/writer evolution and Java 25 build reproducibility. [Avro resolution](https://avro.apache.org/docs/1.12.0/specification/) · [Avro Java](https://avro.apache.org/docs/1.12.0/getting-started-java/) |
| T6-R · Package boundaries | Run the test-only ArchUnit pilot at pull request and release against the approved module/package graph. Build-module checks plus JDK dependency inspection need manual assertions. Include bootstrap and lifecycle conformance. | **Test-only pilot approved.** Verify disallowed domain→Spring and cross-adapter edges and cycles fail, valid paths pass, and Java 25 classes import. A compulsory gate needs a compatible pin and reviewed pilot results. [ArchUnit guide](https://www.archunit.org/userguide/html/000_Index.html) |
